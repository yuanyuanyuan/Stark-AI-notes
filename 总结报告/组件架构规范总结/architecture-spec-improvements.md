### 2. 模板选择决策系统

#### 2.1 智能模板推荐器
```markdown
## 🧭 架构模板智能推荐

### 快速评估问卷 (30秒完成)

**项目规模评估:**
1. 你的应用预计有几个主要功能模块？
   □ 1-2个 (如：简单展示)  
   □ 3-5个 (如：任务管理) 
   □ 6-10个 (如：完整CRM)
   □ 10+个 (如：企业级系统)

2. 预计有几种不同的用户角色？
   □ 不需要登录
   □ 1种角色 (如：个人用户)
   □ 2-3种角色 (如：用户+管理员)  
   □ 复杂权限体系

3. 数据处理复杂度？
   □ 只读数据展示
   □ 基本增删改查
   □ 复杂业务逻辑
   □ 大量数据处理

**推荐结果:**
基于你的选择：3-5个功能模块 + 1种角色 + 基本增删改查
→ **推荐：模板2-中型应用架构** 

**为什么选择这个模板？**
- ✅ 支持3-5个功能模块的组织方式
- ✅ 包含用户认证但不复杂
- ✅ 提供标准的CRUD操作模式
- ⚠️ 如果后期功能增加到8+，建议升级到模板3
```

#### 3.2 常见错误案例分析
```markdown
## ❌ 架构设计常见错误及修正

### 错误1：组件粒度过细
**错误示例**:
```
TaskCard
├── TaskTitle (业务组件)
├── TaskDescription (业务组件)  
├── TaskPriority (业务组件)
├── TaskStatus (业务组件)
└── TaskActions (业务组件)
```

**问题分析**: 拆分过细，增加复杂度但无复用价值

**正确做法**:
```
TaskCard (完整的业务组件)
├── 内部使用基础组件: Button, Badge, Text
└── 不需要拆分为独立组件
```

### 错误2：组件分层混乱
**错误示例**:
```
Page层组件引用关系混乱:
TaskPage → TaskList → TaskForm → TaskPage (循环依赖!)
```

**正确的层次关系**:
```
页面层: TaskPage
├─ 业务层: TaskList, TaskForm (平级关系)
└─ 基础层: Button, Input, Modal
```

### 错误3：状态管理位置错误
**错误**: 把所有状态都放在最顶层组件
**正确**: 状态放在最近的共同父组件

**示例修正**:
```
❌ 错误: App组件管理所有状态 (包括TaskCard的展开状态)
✅ 正确: TaskCard内部管理自己的UI状态
```
```
