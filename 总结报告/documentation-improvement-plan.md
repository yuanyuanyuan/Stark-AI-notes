## 组件命名规范

### 📝 基本规则
组件名称要用"首字母大写"的方式，比如：
- TaskCard（任务卡片）
- UserProfile（用户资料）  
- NavBar（导航栏）

💡 这种命名方式叫做 **PascalCase**（帕斯卡命名法），
   就像人名一样，每个词的首字母都大写。

### 🤔 为什么这样命名？
1. React能识别这是组件而不是普通HTML标签
2. 其他开发者看到就知道这是可复用的组件
3. 符合整个React生态的约定俗成

### 内容表达改进方案

#### 1. 语言风格调整

**改进前**：
```
组件应该遵循单一职责原则，每个组件只负责一个特定的功能。
通过Props接口定义组件的输入参数，保证类型安全。
```

**改进后**：
```
🎯 **组件设计原则**：一个组件只做一件事

**为什么这样做？**
- 就像厨房工具，刀就是切菜，锅就是炒菜，各司其职
- 出问题时容易找到原因
- 其他地方需要时可以直接复用

**具体怎么做？**
- ✅ **好例子**：TaskCard只负责显示一个任务
- ❌ **坏例子**：TaskCard既显示任务，又管理整个列表，还处理用户登录

**Props参数说明**：
组件需要接收外部数据时，就像函数需要参数一样：

```jsx
// 就像函数接收参数
function sayHello(name) {
  return `Hello, ${name}`;
}

// 组件也接收参数（叫Props）
function TaskCard({ title, priority }) {
  return <div>{title} - {priority}</div>;
}
```
```

#### 3. 错误预防和处理指导

**常见错误预防**：
```markdown
## 🛡️ 常见问题预防

### 问题1：组件名称不规范
❌ **错误写法**：`taskcard`、`taskCard`、`task-card`
✅ **正确写法**：`TaskCard`

💡 **记忆技巧**：组件名像人名，每个词首字母大写

### 问题2：忘记导入导出
❌ **错误**：创建了组件但其他地方用不了
✅ **解决**：
```jsx
// 文件末尾一定要有这一行
export default TaskCard;

// 使用的地方一定要先导入
import TaskCard from './TaskCard';
```

### 问题3：Props传递错误
❌ **错误**：`<TaskCard title={title} />`但title是undefined
✅ **安全写法**：
```jsx
// 给默认值
const TaskCard = ({ title = "未命名任务" }) => {
  return <div>{title}</div>;
};

// 或者检查是否存在
const TaskCard = ({ title }) => {
  if (!title) {
    return <div>任务标题缺失</div>;
  }
  return <div>{title}</div>;
};
```

    {title}
  </div>

const TaskCard = memo(({ task, onToggle }) => {

      onClick={handleClick}
      role="button"
      tabIndex={0}
    >
      <h3>{task.title}</h3>
      {task.description && <p>{task.description}</p>}
    </article>
