# 代码评审检查清单

## 📋 概述
此检查清单用于React组件代码评审，确保代码质量和一致性。

## ✅ 代码质量检查

### 📝 代码结构和组织
- [ ] 文件命名是否符合PascalCase约定？
- [ ] 组件名称是否具有描述性和唯一性？
- [ ] 代码结构是否清晰，逻辑分组合理？
- [ ] 函数和变量的命名是否清晰、一致？
- [ ] 代码行长度是否合理（建议不超过100字符）？
- [ ] 是否有适当的空行分隔逻辑块？
- [ ] 是否有复杂的嵌套结构需要简化？

### 🔤 TypeScript类型
- [ ] 所有Props是否都有正确的类型定义？
- [ ] 是否使用了interface而不是type（适用于对象类型）？
- [ ] 泛型使用是否正确和必要？
- [ ] 类型定义是否足够具体，避免使用any？
- [ ] 可选属性是否正确使用?标记？
- [ ] 联合类型和交叉类型使用是否合理？

### 🎨 样式和格式化
- [ ] 代码是否遵循项目的ESLint规则？
- [ ] 代码格式化是否符合Prettier配置？
- [ ] 导入语句是否按类型分组并排序？
- [ ] 是否有未使用的导入？
- [ ] 字符串是否使用一致的引号风格？
- [ ] 对象和数组的格式化是否一致？

## ✅ React最佳实践检查

### 🏗️ 组件设计
- [ ] 组件是否遵循单一职责原则？
- [ ] Props设计是否合理，避免过度传递？
- [ ] 是否正确使用了React.memo（当需要时）？
- [ ] 组件是否可复用和可测试？
- [ ] 是否有适当的错误边界处理？

### 🎭 Hooks使用

- [ ] useEffect的依赖数组是否正确？
- [ ] 是否正确使用了useCallback和useMemo？
- [ ] 自定义Hooks是否以use开头？
- [ ] 是否有正确的清理函数？

### 🔄 状态管理
- [ ] 状态设计是否合理，避免过度状态？
- [ ] 是否使用了合适的状态管理方案？
- [ ] 状态更新函数是否正确（使用函数式更新）？
- [ ] 是否避免了不必要的状态提升？
- [ ] 复杂状态是否使用了useReducer？
- [ ] 状态是否可预测和可调试？

### 🎨 事件处理

## 📝 评审指南

### 评审流程
1. **准备阶段**: 开发者完成自检，准备相关文档
2. **评审会议**: 团队成员共同审查代码
3. **问题记录**: 记录发现的问题和建议
4. **修复验证**: 开发者修复问题后重新验证
5. **归档**: 评审结果归档，用于后续参考

### 评分标准
- **优秀**: 90-100分
- **良好**: 80-89分
- **一般**: 70-79分
- **需改进**: 60-69分
- **不合格**: <60分

### 注意事项
- 保持建设性的反馈态度
- 关注代码质量而不是个人风格
- 优先关注功能正确性和安全性
- 考虑维护成本和可扩展性
- 记录所有问题和建议以便跟踪
