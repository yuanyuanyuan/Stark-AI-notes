## 💡 使用技巧

### 如何让AI更好地理解架构需求
```
请仔细阅读这个React组件架构设计规范，重点关注：

1. 组件分层原则（应用层、业务层、通用层、基础层）
2. 组件分类方法（按技术特性、复用性、复杂度）
3. 架构模式选择（模块化、功能域、分层）
4. 架构设计流程（需求分析→架构设计→组件实现）

然后基于我的具体需求，设计最适合的组件架构。
```

### 如何验证架构设计的合理性
```
请检查我设计的组件架构是否符合React组件架构设计规范：

检查要点：
1. 组件职责是否单一？
2. 组件分层是否合理？
3. 组件间耦合度是否低？
4. 是否具有良好的扩展性？
5. 是否考虑了性能优化？
6. 是否便于团队协作？

如果有问题，请告诉我如何改进，并给出具体的修改建议。
```

### 如何处理复杂业务场景
```
我的业务场景比较复杂，请帮我：

1. 分析业务复杂度
2. 拆分业务域
3. 设计域间交互
4. 规划组件边界
5. 设计数据流

每个业务域都要按照React组件架构设计规范来设计组件架构。
```
