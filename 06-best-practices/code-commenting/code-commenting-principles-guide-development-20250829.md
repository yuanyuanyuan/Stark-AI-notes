# 代码注释原则指南

## 代码注释任务概述

本文档旨在指导如何为代码添加高质量注释，使其对AI系统和人类开发者都更加易于理解。

## 分析步骤

1. **理解代码结构**：分析代码的整体架构和功能模块
2. **识别关键组件**：找出重要的函数、循环、条件语句和复杂逻辑
3. **理解业务逻辑**：把握代码的核心业务目标和实现方式

## 注释内容要求

### 必须包含的注释内容：
- **功能目的**：解释函数或代码块的作用
- **算法逻辑**：说明复杂算法的工作原理
- **假设限制**：指出代码中的假设条件和限制
- **变量含义**：解释重要变量和数据结构的意义
- **边界处理**：说明潜在的边界情况和错误处理机制

## 注释格式规范

### 注释类型选择：
- **单行注释**：用于简短的解释说明
- **多行注释**：用于详细的函数或类描述
- **文档注释**：用于API接口和公共方法的说明

### 注释质量标准：
- 使用清晰简洁的语言
- 避免重复描述显而易见的内容
- 重点关注"为什么"和"如何实现"，而不仅仅是"做什么"
- 保持注释的及时性和准确性

## 最佳实践原则

1. **保持一致性**：在整个项目中使用统一的注释风格
2. **注重实用性**：注释应该提供有价值的信息，而不是废话
3. **及时更新**：代码修改时同步更新相关注释
4. **考虑读者**：为不同层次的开发者提供适当的解释

**重要提醒**：所有注释请使用中文编写，确保符合本地化开发需求。
